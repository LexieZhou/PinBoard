⏺ Good thinking. The current flow navigates to each place individually, clicks
  Save, and wrestles with the popup menu every time. The list-first approach
  would:
  1. Navigate once to /maps/saved/
  2. Click "New list", type the name, hit Next
  3. Use input[aria-label="Search for a place to add"] to add all places in one
  session
  4. Click Done

  This is simpler — no isFirst branching, no Save-menu popup, one stable UI
  context for all places. The main risk is whether the combobox responds to the
  same setNativeValue + input event trick. I'll implement it now.

  The refactor: three injected functions (setupList, addPlaceToList, finishList)
   instead of one big navigateAndSave, service worker drives them in sequence
  with progress still reported per-place.
